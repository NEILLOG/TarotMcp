# 塔羅牌 MCP 主計畫

- 建立日期：2026-10-31
- 以這份文件與 GitHub 為準。先前在 Claude 文件寫的版本（「塔羅牌 MCP 執行計劃」）只是草稿來源，之後不再同步。

## 目標與範圍

這個 MCP 只負責「確定性」的部分：洗牌、抽牌、決定正逆位、依牌陣擺放位置、查詢牌與牌陣。牌與問題之間的解釋由模型負責。

**第一版做**

- 萊德-韋特-史密斯 78 張牌，繁體中文牌義，正逆位可關閉
- 三個牌陣：單張、三張（過去／現在／未來）、凱爾特十字（10 張）
- 牌面圖片為選配，不影響占卜功能
- 每個牌陣位置帶畫面座標，供 Lumi 畫出牌陣圖

**第一版不做**

- 托特、馬賽等其他流派
- 占卜歷史紀錄與回顧
- 牌與牌之間的關係分析（元素、數字、花色統計）
- 即時生成圖片
- 代表牌（significator）

## 架構

```
使用者 ↔ 模型（Claude / Lumi 內的模型）
              │  MCP（stdio）                 │  ITool（之後）
     ┌────────┴────────┐             ┌────────┴────────┐
     │ TarotMcp.Server │             │  Lumi 內建工具   │
     └────────┬────────┘             └────────┬────────┘
              └────────────┬──────────────────┘
                    ┌──────┴───────┐
                    │ TarotMcp.Core │  資料載入與驗證、洗牌、抽牌
                    └──────┬───────┘
                cards.json ┴ spreads.json（內嵌資源）
```

- .NET 10（與 Lumi 一致）。
- `cards.json`、`spreads.json` 以內嵌資源打包，啟動時一次載入並驗證。
- 工具回傳 JSON 字串，欄位為 snake_case；抽牌結果只帶「當下方向」的牌義與關鍵字。
- 工具參數名稱沿用 C# 參數名（camelCase：`spreadId`、`allowReversed`、`cardId`）。

## 資料

### cards.json

78 筆。欄位：`id`、`name_zh`、`name_en`、`arcana`、`suit`、`number`、`element`、`keywords_upright`、`keywords_reversed`、`meaning_upright`、`meaning_reversed`、`image`、`image_prompt`、`source{work, waite_upright_en, waite_reversed_en}`、`review_note`。

- id：大牌 `major_00`～`major_21`；小牌 `wands_01`～`wands_14`，其他花色同理（11～14 依序為侍者、騎士、皇后、國王）。
- 編號依韋特版：力量是 8、正義是 11。
- `element` 只有小牌填（權杖＝火、聖杯＝水、寶劍＝風、錢幣＝土）；大牌留空，因為各傳統的對應不一致。
- 逆位牌義依現代慣例撰寫，常與韋特自己寫的逆位不同；韋特英文原文留在 `source` 供追溯。
- `review_note` 標示與韋特原文差異較大的牌（愚者、教皇、隱者、死神、惡魔、高塔、星星、權杖騎士、聖杯二）。
- 載入時驗證：恰好 78 張、id 不重複與欄位一致、大牌 22 張、四個花色各 14 張、每張都有正逆位牌義與關鍵字、元素規則。

### spreads.json

每個牌陣有 `positions`，每個位置有 `index`、`id`、`name_zh`、`meaning_zh`、`layout{x, y, rotation, z}`。

- `layout.x` 以牌寬為單位、`layout.y` 以牌高為單位（牌高 = 牌寬 × 12/7）；(0,0) 為牌陣中心，x 向右、y 向下為正；`rotation` 是度數；`z` 是疊放層級。
- 單張與三張是原創定義；凱爾特十字依韋特原書第三部第 7 節（PDF 第 118–120 頁）。

| 1 | covers | 覆蓋 | 0 | 0 | 中心 |
| 2 | crosses | 交叉 | 0 | 0 | 橫放 90°，疊在 1 上 |
| 3 | crowns | 上方 | 0 | -1 | |
| 4 | beneath | 下方 | 0 | 1 | |
| 5 | behind | 身後 | 1 | 0 | 依韋特原圖的方向 |
| 6 | before | 眼前 | -1 | 0 | 依韋特原圖的方向 |

## MCP 工具

| 工具 | 參數 | 回傳 |
|---|---|---|
| `list_spreads` | 無 | id、名稱、張數、適用情境 |
| `get_spread` | `spreadId` | 每個位置的名稱、含義、座標 |
| `draw_cards` | `spreadId`、`allowReversed`（預設 true） | 每個位置的牌、正逆位、當下方向的關鍵字與牌義、圖片路徑、座標 |
| `get_card` | `cardId` | 單張牌完整資料（正逆位都有） |

- 工具說明寫明：牌義為反思視角、僅供娛樂與自我探索；醫療、法律、投資、人身安全問題不做絕對性預言。
- 未知的牌陣或牌 id 回傳錯誤並列出可用的選項。

## 抽牌邏輯

1. 以 Fisher–Yates 洗牌，亂數用 `RandomNumberGenerator.GetInt32`（密碼學安全）。
2. 依牌陣張數從牌堆最上方取牌（不放回、不會重複）。
3. 若允許逆位，每張牌各自以 50% 決定正位或逆位。
4. 依位置編號填入，組成回傳結果。

亂數的取用順序固定（先洗牌，再依位置順序決定方向），亂數來源包成 `IRandomSource`，測試時可換成固定序列。

## 雙擊執行檔

這是 stdio 伺服器，使用者直接雙擊時輸入沒有被客戶端導向。程式偵測到後會顯示說明與含實際路徑的設定範例，再等按鍵關閉，不會卡住。

## 牌面圖片

牌面由**兩種素材疊成**，都由其他 AI 生成（Claude 不製作）；MCP 與資料只預留檔案路徑規則。疊圖與文字由使用牌面的程式負責（例如 Lumi）。**兩種素材都是 7:12 滿版、同尺寸，像圖層一樣由下往上疊，座標完全對齊。**

| 圖層（由下往上） | 內容 |
|---|---|
| ① 插畫 | 每張牌一張，滿版，只有畫面；主體避開會被邊框蓋住的位置（見下） |
| ② 邊框範本 | 全副牌共用的一張華麗邊框（暗夜藍黑底、細金線、四角裝飾、上方圓章、下方牌名板），窗口去背透明 |
| ③ 文字（程式畫） | 羅馬數字（圓章）、中英文牌名（牌名板）、逆位標示。不交給 AI 畫：AI 的中文常亂碼，78 張也難以字體一致 |

逆位只旋轉①：以窗口中心為旋轉中心轉 180°，②與③保持正向；旋轉後露出的下緣由牌名板與邊框蓋住，底色填深色。

| 項目 | 規格 |
|---|---|
| 尺寸（兩種素材相同） | 7:12 直式，建議 1400×2400 px（最低 840×1440）；AI 做不到 7:12 時，用最高直式比例生成再置中裁切（`tools/generate_cards.py` 已處理） |
| 邊框範本的窗口 | 約佔寬度 90%、高度 5%～83%；生成時窗口塗純洋紅 `#FF00FF`，去背後存成透明；圓章與牌名板內部塗純黑（由程式在上面寫字） |
| 範本檔案 | `assets/frame/frame.png`（去背後）＋ `assets/frame/frame.json`（`window: {x, y, width, height}`，像素，以範本實際尺寸為準；逆位的旋轉中心 = 窗口中心） |
| 插畫的安全區 | 主體在左右各 10% 以內、上方 9% 到下方 80% 之間，視覺中心約在由上往下 44%；上方 8%、下方 18% 只放背景延伸；背景鋪滿整張 |
| 插畫內容 | 只有插畫；無邊框、文字、數字、浮水印 |
| 插畫格式與路徑 | PNG 母檔，WebP 交付；`assets/cards/<id>.webp`，id 與 `cards.json` 相同；牌背（選配）`assets/cards/back.webp` |

完整的邊框範本提示詞、插畫風格前綴與 78 張場景描述見 [`image-prompts.md`](image-prompts.md)。順序：①先生成並挑出邊框範本、量出窗口；②再試產 3 張插畫（愚者、教皇、聖杯三），疊上邊框預覽，確認主體沒被蓋到、風格搭配；③確認後批次生成其餘。

（2026-11-01 修訂：邊框由程式簡單繪製改成華麗邊框範本，由 AI 生成一次、全副共用；邊框與插畫採相同 7:12 滿版疊圖，避免比例對不上的風險，此為使用者的決定。）

**授權**：AI 生成圖的商用條款因工具而異；自用或 Lumi 內部使用不受影響，要販售前先確認所選工具的最新條款。

## 對話指引

模型光靠牌義就能把牌串成故事，但沒有指引時，每次的結構、長度、語氣都會不同，也可能憑記憶改寫牌義或給出絕對性預言。指引放在 MCP server 的 `instructions`（跨客戶端通用）、工具說明各留一兩句；Lumi 可另外放進系統提示。草稿見 `src/TarotMcp.Server/Instructions.cs`。

**驗證方式（D4）**：同一組牌（用 `TAROT_TEST_SEED` 固定），分別在有指引與沒有指引的情況下各解讀三次，比較結構是否一致、有沒有違背牌義、語氣是否為反思視角。

## 牌義的來源與核對

- 來源：Waite《The Pictorial Key to the Tarot》（1910/1911）英文原文，擷取結果在 [`waite-source-en.json`](waite-source-en.json)。
- 中文牌義是原創改寫，不抄錄現代書籍。牌義是長期演變的傳統，沒有唯一標準；自由度在於用字，核心方向要與主流相仿，才不會與使用者在別處學到的衝突。
- 2026-10-31 已對照主流網站（Biddy Tarot、Labyrinthos）核對七張大牌：愚者、教皇、隱者、死神、惡魔、高塔、星星，方向一致。聖杯二逆位只有部分佐證；權杖騎士逆位尚未找到可讀的對照來源。
- 韋特原文有些詞今天幾乎不用（例如隱者的 treason、星星的 loss），現代版採用現代的方向。
